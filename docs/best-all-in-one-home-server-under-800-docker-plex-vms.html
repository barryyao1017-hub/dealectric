Where Plex goes when the same box runs VMs

Plex's support article on hardware-accelerated streaming (last modified 2026-10-27) says it "is not currently possible inside of virtual machines, as virtual machine hosts do not expose low-level video hardware to the guest operating system." The supported route is Docker. If the Docker host has an Intel Quick Sync CPU, you bind-mount the kernel device (/dev/dri) into the Plex container. It needs an active Plex Pass. Plex's Linux encoder list has Intel VAAPI, NVIDIA NVENC and software x264, with no AMD entry.

So run Plex and your other Docker apps in containers on the host with /dev/dri, and use the couple of VMs for things that need a whole OS, such as Home Assistant or a Windows test box, without a GPU. On Proxmox, give a Plex LXC the iGPU with the container's dev[n] passthrough option (pct manual, Proxmox VE 9.2.13). Don't pass the iGPU to a VM: Proxmox's PCI passthrough page warns that "if you pass through a device to a virtual machine, you cannot use that device anymore on the host."

On the NAS picks you don't need to set anything up. TerraMaster's TOS has Docker Manager with docker-compose and Portainer (NASCompares). TOS 7 adds a Virtual Machines module and lists the F4-424 Pro as compatible (NASCompares, Rob Andrews, 2025-12-15). NASCompares played media on the F4-424 Pro with hardware transcoding enabled, including some 8K.

Not recommended

Aoostar WTR Pro (Ryzen 7 5825U) for Plex. It is the cheapest box here with four bays, but it has Radeon graphics, and AMD is not on Plex's Linux encoder list, so Plex transcodes on the CPU. Consider it only if every player direct-plays.

Barebones plus retail DDR5. The WTR Max Intel has Quick Sync and six bays, but 32 GB of DDR5 takes it past $1,000 before an SSD. The MS-01 SE takes DDR4, not DDR5, so the cheap way to get it is Minisforum's 32 GB / 1 TB build at $775. The $375 barebone was out of stock on 2026-11-13.
