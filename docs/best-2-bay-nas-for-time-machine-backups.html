Setting it up on the DXP2800

  1. Update UGOS Pro to 1.9.0.0035 or later and enable SMB and Bonjour in Control Panel.
  2. Create one shared folder per Mac (Backups-Air, Backups-Pro) and set a capacity quota on each: at least twice that Mac's storage, per Apple, and never so small that Time Machine reports "insufficient space" (UGREEN's own warning). A sparsebundle's maximum size is fixed when it is created, so set the quota before the first backup.
  3. Turn on Time Machine for each share, then on each Mac choose its share in System Settings → General → Time Machine. Use separate NAS user accounts so one Mac cannot read the other's backup.

What is known and what is not

UGREEN's own support article (350) states the firmware and macOS 12 requirements and the per-share quota; reviewers set up Time Machine on the DH2300, DH4300 Plus and DXP4800 Pro without trouble. No sourced report of sparsebundle corruption or macOS 26 failures on UGOS turned up, which is thin evidence rather than clean evidence: macOS 26 (Tahoe) Time Machine failures reported on Synology, QNAP and UniFi units came from SMB signing and credential changes and non-ASCII names, problems any NAS can hit. Test a restore once the first backup completes, on any brand.

Drives and RAID

Two drives in RAID 1 give one drive's capacity and survive one failure; a Time Machine backup that lives only on the NAS is still a single copy, so RAID 1 is about not losing the backup when a disk dies, not a second backup. Two 4 TB NAS drives give 4 TB usable, enough for two Macs with about 1 TB of data each under Apple's 2× rule; 8 TB drives double that.
