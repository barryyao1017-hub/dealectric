What the differences mean

  • Kernel against WireGuard: WireGuard joined mainline Linux in 5.6 (29 March 2020). UGOS Pro 1.19.1 runs 6.18, which is newer than 5.6. DSM 7.3.2 runs 4.4.302+, which is older than 5.6. A container that relies on the host's WireGuard module has nothing to load on DSM.
  • Electricity over a year with drives active (maker's figure × 8,760 h): DXP2800 16.38 W → 143.5 kWh; DS225+ 16.98 W → 148.7 kWh; AS5402T 22.9 W → 200.6 kWh; TS-264 29.086 W → 254.8 kWh. The TS-264's built-in WireGuard costs 254.8 − 143.5 = 111.3 kWh a year more than the DXP2800 running WireGuard in a container. The test setups differ: UGREEN used one Seagate 2 TB drive, QNAP filled both bays, and Synology and Asustor don't tie a drive setup to their figures.
  • Why the drives-active figure is the one to plan on: UGREEN says Docker containers and always-active databases that touch the storage pool can keep drives from hibernating. A DNS filter answering and logging every query in the house works that way all day. Put the containers on an NVMe volume so the hard drives can still sleep. The DS225+ spec page lists no M.2 slot for that.
  • Room for containers: 8 GB (DXP2800, TS-264) ÷ 2 GB (DS225+) = 4× the memory before any upgrade.

WireGuard on each NAS OS: why the kernel version decides

WireGuard is a Linux kernel feature. The two common containers, wg-easy and linuxserver/wireguard, don't bring their own copy. They use the host's kernel module, so the NAS OS's kernel decides whether they run. Pi-hole and AdGuard Home have no such requirement and run as ordinary containers. The DNS side only needs port 53 free.

  • UGREEN UGOS Pro (DXP2800): UGOS Pro 1.19.1.0126, released 31 August 2026, upgraded the kernel to 6.18 (Marius Hosting). Marius Hosting's UGREEN guide runs AdGuard Home in Docker with network_mode: host, moves its admin page from port 80 to 9080 and keeps DNS on port 53. Before you deploy, run modprobe wireguard over SSH to check the module loads. $389.99; buy: https://dealectric.com/go/ugreen-nasync-dxp2800

Not recommended
