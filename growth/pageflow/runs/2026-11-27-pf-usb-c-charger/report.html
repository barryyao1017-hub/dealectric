How one run works

  1. Ledger. Every page is tagged with its cluster, page type and shopper traffic. Visits per page for each cluster and page type become the starting score for new lines.
  2. ChatGPT's choices. Six plain chats per cluster on broad questions show which questions it asks back and which figures it sorts its picks by.
  3. Decision map. One research agent per cluster ranks what buyers decide on, finds the real breakpoints, reads what is new, and places our products against the leading rivals. Each line on the map is one question one page could answer.
  4. Gates. A line is queued only if it is sourced, one of our products is honestly in the top three, no page of ours covers it, and people search it. ChatGPT's own results are then read for each question before any research is paid for.
  5. Build. Our own prices are re-read on the stores, then each page goes through the existing research method and its checks, and is published.

The write-up is growth/pageflow/README.md; the code is tools/pageflow/.

The one choice: where the routine runs

The plan said a stage of the 06:37 daily sweep. The same day you moved the weekly catalog upkeep out of the sweep into a Claude scheduled task, so that it shows in the app's Scheduled list and a session supervises it.

My recommendation: a Claude scheduled task, daily after the sweep, building up to 3 pages a day with publishing on. A session can then handle a merge conflict or a failed gate, which a script cannot. The cost is one more scheduled task and daily use of the plan's research quota.

The alternative is the sweep stage: no new task, but unattended, and a failed run waits for the next morning.
